# T06 邮箱验证码登录页面

[返回总览](../README.md)

状态：**进行中**。前置：[T04](T04-app-api-session.md)。绑定后真实登录验收依赖 [T05](T05-account-security-ui.md)。

## 目标与范围

在现有账号登录内部增加邮箱验证码方式，账号密码保持默认。使用同一个会话与原导航结果，不改云端 Token 登录和账号 QR 挑战协议。

## 先读入口

- `src/features/auth/LoginScreen.tsx`、`src/core/auth/accountAuth.ts`、T04 API。
- 现有 account/cloud 切换、设备名、提交按钮和登录成功 goBack 行为。
- 双语登录文案、主题和现有键盘组件；相关 auth module 及会话回归测试。

## 必须完成

1. account 分支增加 password/email 局部方式切换，默认 password；cloud 分支保持原结构，不扩展路由参数或设置全局默认偏好。
2. 邮箱验证码表单包含邮箱、验证码、获取验证码和登录按钮；复用既有 deviceName 校验和提交。只支持已绑定已有账号，不增加注册入口或登录后自动绑定跳转。
3. SMTP 接受后按服务器时间展示 60 秒冷却；未绑定/停用地址使用一致的对外时间规则。不额外弹“若已绑定”解释或宣称已到收件箱。提供检查地址/垃圾邮件和稍后手动重发的简短说明；邮箱格式、网络/服务失败和请求频繁正常提示。
4. 用户主动点击登录，code 输入支持粘贴及平台允许的系统验证码填充，不读取邮件权限、不自动提交。认证失败按定稿统一文案，提示可以切换密码登录后在账号与安全绑定。
5. 邮箱变化清空旧 code/challenge，方式切换取消请求并清理敏感输入；回邮箱验证码方式不能靠切换或大小写变体绕过服务端冷却。App 回前台重算剩余时间，不创建永久倒计时服务。新验证码成功发送后旧码失效，晚到邮件提示使用最新验证码，不延长 5 分钟有效期。
6. 登录调用 accountAuth 方法，成功清空验证码并沿用原返回流程。重启恢复、电脑目录刷新、权限、deviceToken 及账号/云端独立性都交给已有链路。
7. 发送和登录各自维护必要提交状态，防重复点击；登录期间切换/退出后迟到结果不能写入 session。输入和发送错误只影响本表单。
8. 原密码用户名/密码/设备名、QR 挑战和云端 Token 输入/粘贴继续可用；仅修改当前需求相关 UI 和文案。
9. 使用邮箱键盘、关闭自动大写并支持粘贴；投递地址保留原输入，不剥离点号/+tag。邮箱输入与查找遵守统一规则，不对域名作白名单限制。

## 防止过度设计

不提取 AuthStrategy、登录插件、多步骤向导或统一认证页面工厂。不新建邮箱登录缓存、持久化登录方式、自动注册或全局倒计时。LoginScreen 变大时只拆邮箱验证码表单等明确边界，不重构所有登录方式。

## 验收

- 初始是账号密码，邮箱验证码切换易理解；验证码请求受理后直接倒计时，无解释性弹窗，也不宣称已到收件箱。
- 错误、过期、重发、冷却、修改邮箱地址、切换方式、回前台和重复提交正常。
- 验证码填充不自动登录，邮箱验证码登录成功返回原账号与导航，退出/取消拒绝迟到 session。
- 密码、QR、云端 Token 及电脑目录回归通过；中英文 key、typecheck/lint 和针对性会话测试通过。
