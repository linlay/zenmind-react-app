# T05 账号与安全、绑定与解绑页面

[返回总览](../README.md)

状态：**进行中**。前置：[T04](T04-app-api-session.md)。

## 目标与范围

实现用户确认的成熟流程：“用户 → 账号与安全 → 邮箱”。首次绑定不验密码；解绑验证当前邮箱。保留原账号信息、QR 授权、来源和退出入口，避免重复页面职责。

## 必须完成

1. 用户页增加明确的“账号与安全”入口，使用既有列表风格；仅云端 Token 登录不等于账号已登录，无账号会话时提示先进行账号登录。
2. 新 AccountSecurityScreen 按需查询 security，展示 username 与邮箱。未绑定显示“未绑定”，已绑定显示完整邮箱地址，长地址可换行，不用掩码或省略号代替完整展示；加载和失败分别显示，失败提供重试，不能用失败冒充未绑定。
3. 点未绑定行进入 EmailBindingScreen：邮箱地址、验证码、获取验证码和确认绑定。不增加密码输入、重新登录或最近认证检查。
4. 已绑定页面提供解绑入口。EmailUnbindingScreen 只展示服务端完整邮箱地址、验证码与确认解绑，不让用户修改目标邮箱地址；验证码发给服务端当前绑定邮箱地址。
5. 解绑前明确确认“解绑后该邮箱无法用于邮箱验证码登录，已有登录保持有效”；确认后提交验证码。邮箱地址不可用显示人工处理说明，复用已有支持渠道，不建立客服系统。
6. 成功返回账号与安全并重新查询真实摘要；解绑显示未绑定，允许再次绑定。绑定成功不得创建第二个会话，解绑不得调用 logout。
7. 按账号及 generation 拒绝迟到查询；页面离开/账号退出取消操作。邮箱更改清空 code/challenge，发送结果只能用于当时输入。回前台按服务端时间重算倒计时。
8. 新页面沿用主题、NativeWind、safe area、键盘滚动和 header。中英文 key 同步；仅对两页面确实重复的输入/倒计时行为提取一个局部组件或 hook，不能为了三种用途强制统一整页。
9. 邮箱输入采用邮箱键盘、关闭自动大写，允许粘贴。绑定及解绑验证区域提供“检查邮箱地址和垃圾邮件，60 秒后可重新获取”的简短说明；邮件晚到不延长有效期，SMTP 接受后才进入正常倒计时，不声称已到收件箱。

## 防止过度设计

不扩展成密码修改、安全设备、MFA、登录历史或资料中心。不单独建设直接换绑、支持工单、全局账号安全状态、通用验证向导或表单引擎。页面、API、session 保持现有边界；邮箱不进入聊天 SQLite/MMKV。

## 验收

- 用户入口可达、返回自然，账号/云端状态区分正确；未绑定行一点击就进入绑定。
- 绑定无需密码，账号安全及解绑页显示完整邮箱；解绑必须当前邮箱验证码，目标不能自行改动。
- 解绑后仍已登录且可绑定新邮箱地址；断网或查询失败不会显示虚假未绑定。
- 错码、过期、限流、邮箱地址占用、账号退出与重复提交都有正确反馈；旧响应不覆盖新表单。
- 键盘、粘贴/系统验证码填充、滚动、safe area 和双语人工检查；typecheck/lint 与 i18n key 检查通过。
