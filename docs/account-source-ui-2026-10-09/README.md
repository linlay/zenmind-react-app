## 缓存处理指导

2026-10-09 补充决定：**手机本地缓存可以完全清除，不要求保留、迁移、匹配或兼容旧数据。** T05 接入新账号/来源模型时统一清空旧聊天缓存、目录快照和旧缓存映射，从空缓存开始按当前账号及来源重新拉取。旧本地消息、timeline、草稿和未发送 outbox 不要求恢复，也不得作为新来源的待发送请求重放。通过现有 service/repository 清理，不增加缓存迁移、归属认领、备份恢复或通用清理框架。

清空后产生的新缓存仍按账号/来源隔离；离线有所属缓存就展示，没有就显示空态，不保证旧离线历史可用。不为此新增每次启动或切源强制清空的规则。账号凭据、来源选择记录、主题和语言设置不属于聊天缓存；服务端历史、账号设备记录和远端任务也不在清除范围。清空本地缓存不能替代当前请求失效、来源切换一致性或服务端账号鉴权。

## 最小实现约束

**绝对不允许过度设计。每一处改动必须对应上表的一项行为或已证实的接口缺口。**

1. 先验证已有能力。能复用就复用，能删除就删除；已满足需求的任务用证据关闭，不为清单而造代码。
2. 只有一个来源选择真源。扩展现有 activeDesktop/账号边界及订阅，不并排增加多个 store、Provider 或本地镜像状态。
3. 延续现有分层：页面组合 UI；core 处理认证/连接；feature service/repository 处理业务；SQLite 保持聊天真源，MMKV 延续目录镜像与设置用途。
4. 复用现有身份服务、设备记录、Hub Manager、transport、chatSyncService、repository、WebApps runtime 和主题 Provider，不另建框架。
5. 不增加通用状态机、权限引擎、插件注册表、同步引擎、设备连接池、缓存迁移框架、设置渲染器或独立 presence 服务。确有现有部署无法满足的证据，先记录必要的最小调整。
6. 不长期保留新旧运行路径、扫码凭证回退和重复 API 合成。替换完成的同一任务清理无引用代码；删除仅服务于旧缓存匹配和迁移的兼容读取，不保留可达旧电脑配对登录链路；云端现有合法 Token/Cookie 接入不在清理范围。
7. 不顺手重构无关模块，不扩展套餐、积分、记忆库、硬件指纹、历史设备审计或新云端应用能力。
8. 不盲目增加 schema、存储表、JWT 格式、依赖或配置开关；先证明已有模型无法表达真实需求。依赖变更只改 package.json，不安装、不修改 lock。
9. UI 使用既有 token、图标、Header、列表与 NativeWind 静态 className；不另起视觉体系，不猜 safe area/tab 高度。
10. 清理是每个任务的交付条件。修改前记录原有状态，结束核对差异与临时配置；本功能按上述决定允许清除手机本地缓存，不删除服务端数据、用户设置、既有代码改动或缓存范围外归属不明文件。

## 最小架构落点

- **账号有效电脑**：Hub 的 Desktop 注册表是归属、名称和撤销的唯一持久化来源，现有 Manager 提供在线状态；App 单次读取 Hub 目录，不与 Identity 登录会话合成双目录。
- **在线状态**：Hub 现有连接 Manager 是依据，最近登录时间和 Token 有效期不等于在线。
- **连接授权**：Hub 与 Desktop 在现有签发/验证链路补齐目标授权；不创建第二套认证体系。
- **当前来源**：手机端唯一的可订阅 cloud / desktop 选择；现有 feature service 统一协调选择、scope 与连接，页面不直接写入认证/数据库或自行回滚。
- **内容与缓存**：手机本地云端缓存按账号、电脑缓存按账号＋设备隔离，服务端云端保持原有行为；复用现有 scope 与 repository；清空旧缓存后重新拉取，不保留旧缓存匹配或迁移链路，不复制一套聊天模型。
- **应用与视觉**：复用现有 WebApps Provider 生命周期和 AppThemeProvider。

具体类型、存储编码和凭证字段以 T00 核实后的最小契约为准；本计划不预先规定一批新文件/类。
