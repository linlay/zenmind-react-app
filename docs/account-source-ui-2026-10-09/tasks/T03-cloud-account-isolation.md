## 当前决定

用户明确要求“云端的保持现状，先不改”。本阶段保留现有云端 Platform、WebClient、登录、Token/Cookie、本地调试、管理接口、数据查询、资源、推送及 Agent 工具行为，不推进新的云端账号模式。

App 云端连接沿用现有可接受凭证，不强制切换为手机账号 JWT。手机账号继续用于设备、电脑授权、来源选择和本地缓存；本地账号缓存分区不等于新增服务端隔离。电脑授权继续按 T01/T02 执行。

## 本阶段不执行

- 不部署本次 T03 补丁、不启用新的 `auth.identity-api-base-url`，不修改现有 issuer、验签 key、Token/Cookie 或云端配置。
- 不为 T03 调整 Principal、source、SQL、归档、资源、HTTP/WS/SSE、推送或 Agent 工具权限。
- 不新增租户、schema、历史归属认领/迁移或云端 WebApps。
- 不继续修补云端影响评估问题来扩展本阶段范围；报告保留为历史证据。

## 已应用补丁与计划状态的区别

代码收敛已执行：核对执行前差异后，逐项撤除 Platform 的 52 个已跟踪文件修改与 5 个任务新增文件；该仓库工作区恢复干净。App 云端 HTTP、WS 和同源资源恢复原有 authMode/accessToken，不向云端发送手机 Identity JWT。

这些改动不属于本阶段交付，已按任务差异剥离，未整仓 reset、覆盖原有用户改动、部署或修改真实配置。回归与清理证据见 [执行状态](../implementation-status.md)。

## 历史记录

原任务曾补充稳定 `account_id`、既有 source SQL 查询、资源/观察/推送边界，并进行了本地测试。相关实现与测试记录保留在[执行状态](../implementation-status.md)及[影响评估](../impact-assessment.md)，不代表实际部署或兼容性验收通过。

影响评估复现的管理控制面拒绝、模式适用范围和 Agent 跨账号置顶问题，以及双账号/生产规模性能验收，随 T03 一并暂缓，不作为本阶段新增功能的修复任务。Desktop 退出问题仍由 T02 处理。

仅在用户明确恢复云端改造后，重新核对现有凭证、管理职责与必要缺口；不自动沿用此前改造范围。
