## 目标

清空旧本地缓存后，所有对话读写使用所选来源；离线时只展示新链路产生的所属缓存，无缓存就显示空态，切换不串数据、不停止远端任务。

执行前遵守[总览的最小实现约束](../README.md#最小实现约束)，重新核对最新工作区。已具备能力可以通过验收证据关闭，不强制新增代码。

云端按现有服务端契约读取，本任务的账号 scope 仅约束手机本地缓存；T03 暂缓，不要求新增云端隔离。

## 当前事实

- 当前同步协调器并行启用默认源与一个 Desktop，首页/目录会混排，不能只改显示名称。
- 现有 scope 与 repository 可复用；按补充指导清空旧缓存和映射，删除旧缓存匹配分支，不再核实或迁移旧缓存归属。
- 设备激活现在多处要求在线，要支持离线缓存需拆开本地选择和远端连接条件。

以上为建档时本地静态核实，不能直接代表目标环境已部署。

## 最小变更

1. 缓存按账号和来源隔离，切源使迟到回调失效；不自动重发 query，不迁移或认领旧聊天数据；认证、来源配置、远端数据和用户原始文件保留。
2. 复用现有 repository 与 scope，为手机本地云端缓存按账号、电脑缓存按账号＋设备建立干净范围；不匹配旧 Profile，不绕过数据库入口，不建立第二份数据模型。
3. 首页、搜索、Agent/Team 目录、新对话目标、详情与分页总数全部按当前账号/来源读取；先在 repository 约束再分页，不能只过滤已加载第一页。
4. 缓存按账号和来源隔离，切源使迟到回调失效；不自动重发 query，不迁移或认领旧聊天数据；认证、来源配置、远端数据和用户原始文件保留。
5. 在现有 feature service 收口一个来源切换入口，统一协调选择、scope 与连接。在线目标失败保持或恢复一致的原来源上下文并反馈；离线有效电脑无需凭证即可提交本地选择，有所属新缓存就展示，没有就显示离线空态，发送/创建/应用操作不可用。UI 不自行提交或回滚，不新增事务/状态机框架。
6. 使用现有请求取消、身份/scope 检查和订阅生命周期处理切换，保证旧请求不会写入新 scope；新链路未发出的请求保留正确来源，不能转发给新来源。
7. 只保留当前所需连接和既有共享 transport，不为每台设备创建长期同步实例。切换不调用 stop/cancel 业务指令，切回沿现有历史补拉恢复远端任务；无需恢复被清除的本地历史。
8. 删除旧缓存匹配、认领和迁移兼容代码；清空与重建复用既有缓存初始化入口，不新建迁移管理器或备份恢复流程。
9. 通知与深链读取所属来源后校验账号权限，防止来源切换后打开错误 scope 的会话。

## 不做与禁止扩展

- 不新建通用同步引擎、缓存框架、设备连接池或第二份 timeline 状态。
- 不为了来源选择重写数据库 schema、迁移聊天表或复制全库；确有必要时先在 T00 记录原因。
- 不保留、匹配、认领或迁移旧本地缓存；不通过名称或当前账号猜测旧数据归属，不清除服务端历史或远端任务。
- 不给实时推送另加全量扫描，不在页面读取 SQLite/MMKV/Socket。
- 不因切换而重建无关页面或停止服务端任务。
