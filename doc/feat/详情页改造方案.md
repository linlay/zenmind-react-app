**新目标**
不要把 mobile 详情页继续当 IM 消息列表修补。目标应改成：**mobile 与 web 共享同一种“事件驱动会话运行台”模型**，只是渲染介质不同。

最终形态：

```text
WS / /api/chat events
  -> protocol normalizer
  -> single timeline reducer
  -> materialized projections
       -> home summary / SQLite messages
       -> detail timeline state
       -> runtime awaiting / artifacts / usage
  -> virtualized mobile timeline renderer
       -> native markdown renderer
       -> tool / plan / awaiting / artifact blocks
```

**核心原则**

1. `event -> timeline` 只能有一套 reducer。现在 `messages`、`runtimeState`、页面 UI 各自拼状态，会天然产生丢事件、重复判断和渲染偏差。
2. SQLite 仍是聊天真源，但详情页热路径不把每个 streaming delta 都落库。落库的是 conversation/message 投影和必要的 reconcile snapshot。
3. Markdown 不再继续自研到极限。移动端引入原生 Markdown 基座，但外层保留项目自己的 block registry、资源 resolver、流式策略和 timeline 语义。
4. web 的 `conversationReplay + processEvent + buildTimelineDisplayItems` 是语义参考，不是直接复制 React DOM UI。

**数据层重构**
新增 `src/features/chatTimeline/`，把当前散落在 `chatProjector.ts`、`runtimeState.ts`、`chatRealtimeUiState.ts` 的逻辑收口：

- `protocolNormalizer.ts`：统一 `request.query/content.* / reasoning.* / planning.* / tool.* / awaiting.* / run.* / usage.* / artifact.*` 字段读取。
- `timelineReducer.ts`：输入单个 normalized event，输出不可变 `TimelineState`。
- `timelineDisplay.ts`：把 nodes 变成 FlashList 扁平 item：`query`、`run-header`、`reasoning`、`tool-group`、`planning`、`content`、`awaiting`、`run-meta`。
- `messageProjection.ts`：从同一个 reducer 结果派生 SQLite `messages/conversations` 投影，删除现在另一套只处理 `request.query/content.*` 的投影逻辑。

这样 web 图 1 里的“思考过程、查找文件、读取文件 x5、工具结果、计划确认、最终 Markdown 表格”都会有对应节点；mobile 图 2 那种只剩 assistant 文本的情况会从模型层消失。

**Markdown 基座**
选择方向：`react-native-enriched-markdown` 做 native Markdown 基座，不用 `react-native-markdown-display`。官方 README 明确它是 native text 渲染、CommonMark/GFM、LaTeX、文本选择、可访问性、New Architecture，并且有 RN 版本兼容表；`react-native-markdown-display` 自己的 README 已标注不再积极维护并建议迁移。

关键决策：

- 当前项目 RN `0.81`，按官方兼容表只能选 `react-native-enriched-markdown 0.4.x` 这一档；如果要求最新 GFM table streaming，则要把 Expo/RN 升到支持 `0.6.x` 的区间。
- 如果接受一次更完整的工程升级，建议同时评估 `react-native-streamdown`：它基于 enriched markdown，专门处理 token-by-token incomplete markdown，并把处理放到 Worklets Bundle Mode 背景线程；但它要求额外 Babel/Metro 配置，GFM table streaming 又要求 enriched `>=0.6.0`。
- 因为你要高标准，我建议把“RN/Expo 升级到 enriched 0.6 可用区间”列入同一改造项目的前置工程项，而不是长期 pin 在 0.4.x 上做兼容妥协。

参考：
[react-native-enriched-markdown](https://github.com/software-mansion-labs/react-native-enriched-markdown)，[react-native-streamdown](https://github.com/software-mansion-labs/react-native-streamdown)，[react-native-markdown-display](https://github.com/iamacup/react-native-markdown-display)

**渲染层重构**
替换 `ChatDetailMessageList` 为 `ChatTimelineList`：

- FlashList 数据源是 `TimelineDisplayItem[]`，不是 `ChatMessageItem[]`。
- 每类 item 一个 memo row：`UserQueryRow`、`ReasoningRow`、`ToolGroupRow`、`ContentRow`、`PlanningRow`、`AwaitingRow`、`RunMetaRow`。
- 左侧 rail 只在 flow item 中出现；用户 query 保持右侧蓝色气泡。
- `reasoning/planning/tool result` 默认折叠，大内容展开后才渲染 Markdown/JSON。
- `content` 节点使用新的 `ConversationMarkdownRenderer`，内部接 enriched/streamdown。
- `tool.result` 的 JSON/长文本用专用 `StructuredPayloadViewer`，支持复制、横向滚动、行数截断、展开。
- `awaiting.ask/answer` 同时进入 timeline；overlay 只负责当前待交互输入，不再承担历史展示。

**交互对齐**

- query：复制、重问、新对话重问。
- run：复制整轮 transcript、停止/续接状态、用量展示、耗时展示。
- reasoning/planning：展开/折叠，完成后自动折叠，但用户手动展开后不再自动收起。
- tool：同名连续工具合并，状态点、次数、参数、结果、复制按钮完整展示。
- Markdown code block：复制、语言标签、长代码折叠、等宽字体、横向滚动。
- 资源链接：统一走 `chatResourceResolver`，处理 `/api/resource` 鉴权下载、图片代理、附件打开。
- Mermaid/ECharts/HTML：不塞进 Markdown renderer 黑盒，走 `customBlockRegistry`，按需加载 WebView/Canvas 渲染器。

**性能设计**

- reducer 单次 O(n) replay；实时事件 O(1) 命中 node map。
- FlashList 全扁平列表，不在 row 内嵌长列表。
- row props 只传稳定 id 和 node snapshot，避免整页重渲染。
- Markdown 分三态：离屏不解析、可见才解析、streaming 用 Streamdown/enriched streaming；大块展开才解析。
- 工具结果和 JSON 不参与普通 Markdown parse。
- reconcile 后生成 timeline snapshot 签名；未变化不替换列表 data。
- 图片、HTML、Mermaid、ECharts 全部 lazy mount，离屏销毁或保留轻量 placeholder。

**实施阶段**

1. 抽出 `chatTimeline` reducer，并用 `doc/feat/ws响应.json` 做 golden fixture。
2. 让 `projectRemoteChatDetail` 改为调用 reducer，同时派生 `messages` 和 `timelineState`。
3. `chatSyncService` 实时事件改走同一 reducer，删除 runtime/message 双轨 patch。
4. 替换详情页列表为 `ChatTimelineList`，先接完整事件类型但保持 UI 轻量。
5. 引入 enriched/streamdown Markdown 基座，迁移 `ConversationContentRenderer` 为 wrapper/adapter。
6. 接资源 resolver、tool viewer、custom block registry。
7. 更新 `doc/kb`：模块职责、公共入口、详情页运行链路和规则都要同步。

**验收标准**
同一份 `ws响应.json` 在 mobile 上必须展示：用户 query、每段 reasoning、工具调用和结果、plan/awaiting 交互、最终 Markdown 表格、run 完成信息。性能上，千级事件 replay 不阻塞首屏，streaming 时不全量重算列表，展开大工具结果不拖慢滚动。
