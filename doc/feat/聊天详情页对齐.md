# ChatDetailScreen 功能对齐方案

## Context

当前 `zenmind-mobile` 的 `ChatDetailScreen.tsx` 已具备完整的对话详情页基础结构（FlashList 消息列表、骨架屏、DrawerPanel、chatSyncService 实时同步），但与 `zenmind-react-app` 的 `ChatAssistantScreen.tsx` 相比，缺少多个核心交互功能。本方案旨在无冗余代码、实现优雅的前提下，将功能完整对齐。

---

## 现状对比

| 功能                | react-app                                    | mobile（当前）                     | 差距                 |
| ------------------- | -------------------------------------------- | ---------------------------------- | -------------------- |
| Composer 输入框     | 高度自适应、停止按钮、语音输入、WebView 工具 | 简单 TextInput                     | 重大差距             |
| ChatAwaitingOverlay | 三种模式 + 动画面板                          | 无（仅有 awaitingCard 轻量展示）   | 缺失                 |
| 计划/推理折叠       | 自动折叠逻辑                                 | 无                                 | 缺失                 |
| 可见性追踪          | onViewableItemsChanged                       | 无                                 | 缺失                 |
| 边缘弹跳            | useVerticalEdgeBounce                        | 无                                 | 缺失（**后置评估**） |
| 烟花动画            | useFireworksAnimation                        | 无                                 | 缺失（可选）         |
| 复制/边缘提示       | copyToast, edgeToast                         | 无                                 | 缺失                 |
| 前端工具 Overlay    | ChatFrontendToolOverlay                      | 无                                 | 缺失                 |
| Markdown 流式       | streamingTail + frozenBlocks                 | ConversationContentRenderer 已支持 | 已对齐               |

## 改造计划

### Phase 1: Composer 组件增强

**目标文件**: `src/features/chatPersistence/components/Composer.tsx`（新建）

从 react-app 移植 `ChatTextComposer` 逻辑：

- 高度自适应（1-6行）
- streaming 状态显示停止按钮（红色方块）
- 语音输入按钮（占位，后续扩展）
- `onStop` 回调支持停止流式响应

**关键实现**:

```typescript
// 高度自适应
const handleContentSizeChange = useCallback((event) => {
  const contentHeight = Math.max(minHeight, Math.min(maxHeight, event.nativeEvent.contentSize.height));
  // 计算 visibleRows
}, []);

// streaming 时显示停止按钮
{streaming ? (
  <Pressable onPress={onStop} style={styles.stopButton}>
    <View style={styles.stopIcon} />
  </Pressable>
) : (
  <Pressable onPress={onSend} disabled={!canSend}>
    <Text>发送</Text>
  </Pressable>
)}
```

**stopStreaming 实现**:

- chatSyncService 当前没有公共 `stopStreaming` 方法
- 需要通过 `stopAttachedRun(conversationId)` 实现停止流式
- **方案 A（推荐）**: 在 chatSyncService 添加公共 `stopStreaming(conversationId)` 方法，内部调用 `stopAttachedRun`
- **方案 B**: 在 ChatDetailScreen 中直接调用 `chatSyncService.stop()`（会影响所有会话）

### Phase 2: ChatAwaitingOverlay 组件

**目标文件**: `src/features/chatPersistence/components/ChatAwaitingOverlay.tsx`（新建）

**与 awaitingCard 的关系**:

- `awaitingCard`（现有）: 轻量展示，位于 runtimeSection 内，单卡片形式，仅展示 prompt/answer
- `ChatAwaitingOverlay`（新建）: 全屏覆盖层，带动画，支持 `question/approval/form` 三种交互模式

**实现三种模式的覆盖层**:

- `question` - 问答确认对话框
- `approval` - 审批对话框
- `form` - 表单输入对话框

**动画规格**:

- 遮罩透明度: `maskOpacity` (0 → 0.5)
- 面板滑动: `sheetTranslateY` (屏幕高度 → 0)
- 弹簧参数: `damping: 18, stiffness: 220`

**触发条件**: `runtimeState.awaiting` 存在时显示，覆盖于 Composer 上方

### Phase 4: 可见性追踪 + FlashList 优化

**目标文件**: `src/features/chatPersistence/ChatDetailScreen.tsx`（修改）

```typescript
const viewabilityConfig = useRef({
  itemVisiblePercentThreshold: 1,
  minimumViewTime: 80,
}).current;

const [visibleMessageIds, setVisibleMessageIds] = useState<Set<string>>(new Set());

const onViewableItemsChanged = useRef(
  ({
    viewableItems,
  }: {
    viewableItems: Array<{ item?: ChatMessageItem; isViewable?: boolean }>;
  }) => {
    const nextVisibleIds = new Set<string>();
    viewableItems.forEach((item) => {
      if (item.isViewable && item.item) {
        nextVisibleIds.add(item.item.messageId);
      }
    });
    setVisibleMessageIds(nextVisibleIds);
  }
).current;
```

**FlashList 配置**:

```typescript
<FlashList
  // ... 现有配置
  viewabilityConfig={viewabilityConfig}
  onViewableItemsChanged={onViewableItemsChanged}
/>
```

**visibleMessageIds 消费逻辑**:

1. **图片懒加载**: 只对可见区域内的消息加载图片（利用 `onImagePress` 回调）
2. **阅读状态同步**: 当消息变为可见时，更新 SQLite 中该消息的 `readAt` 时间戳
3. **性能优化**: 配合 FlashList 的 `drawDistance`，确保可见区域外不占用渲染资源

## 注意事项

1. **边界约束遵守**
   - 页面不直接操作 SQLite / WebSocket
   - 所有实时写入继续走 `chatSyncService`
   - 影响首页摘要的持久化改动同步刷新 MMKV 快照

2. **性能优先**
   - FlashList 已有的 `drawDistance={420}` 保持
   - `Memo` 包装所有可复用组件
   - 避免不必要的重渲染

3. **代码复用**
   - 跨项目的代码移植，保持相同命名和结构
   - 注释标注来源（如 `// Adapted from react-app/...`）

4. **Phase 5 后置**
   - 边缘弹跳手势复杂度较高
   - 当前方案暂不包含，如需实现需独立评估工时
