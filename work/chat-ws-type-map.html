对话详情页 WS 协议 type 使用索引

这份 HTML 把当前项目里对话详情页相关的 WebSocket type 拆成三层： 传输 request type、后端聊天事件 event.type、以及 app 内部同步事件 ChatSyncEvent.type。 每一项都标出使用地址和在详情页里的作用。

一眼看链路

ChatDetailScreen 组合 Header、Timeline、Composer、AwaitingDock。页面只调用 chatSyncService。
Conversation Controller 订阅 scoped sync event，发送、停止、继续、reconcile 都在这里接入。
chatSyncService 业务中枢。处理 request、stream、push，落库并投影 timeline。
chatWsTransport 聊天协议 adapter。封装 /api/query、/api/attach 和 push 归一化。
sharedWsTransport / WsClient 底层 socket。负责 endpoint、namespace、frame、心跳、重连、request/stream/push。

传输地址与 frame 规则

HTTP / agent-platform profile

active HTTP profile 使用 getApiBaseUrl()，在非开发 override 时自动推导到 ws(s)://<base>/ap/ws?token=<accessToken>。此模式默认不发送 namespace。

src/core/ws/wsClient.ts:147、src/core/api/activeWsTransport.ts:37

Desktop WS profile

使用 profile 保存的精确 wsUrl，token 可走 query 或 subprotocol。 聊天业务 namespace 为 ap，桌面会话/认证事件 namespace 为 d。

src/core/ws/wsClient.ts:177、src/core/ws/wsTransportConfig.ts:1

统一 frame

出站统一发送 { frame: "request", type, id, payload, ns? }。 普通 request 等 response；stream request 等 stream；订阅消息走 push。

src/core/ws/wsClient.ts:400、src/core/ws/wsClient.ts:609

排查提示

不要把三种 type 混在一起。 /api/query 这类是 WS request type； content.delta 这类是后端聊天协议事件 type； conversation.timeline.replace 这类只是 app 内部发给 UI 的同步事件。 对话详情页当前以 conversation.timeline.replace 作为主消费面，旧的 message/runtime delta 事件仍会发出，但详情页会跳过它们。
